# 04_Site_Architecture.md (v1)

# Цель документа

Определить структуру сайта до начала дизайна и разработки.

Каждый экран существует не сам по себе, а отвечает на конкретный вопрос
рекрутера.

------------------------------------------------------------------------

# Общая логика

Сайт должен вести пользователя по простой последовательности:

Кто это? ↓

Почему мне стоит обратить внимание? ↓

Как этот человек мыслит? ↓

Какие результаты уже есть? ↓

Хочу поговорить лично.

------------------------------------------------------------------------

# Экран 1. Hero

## Цель

За первые 10 секунд объяснить:

-   кто перед пользователем;
-   на какую роль претендует кандидат;
-   почему стоит продолжить просмотр.

## Содержимое

-   фотография;
-   имя;
-   должность;
-   краткое позиционирование;
-   опыт;
-   кнопка "Посмотреть кейсы";
-   кнопка "Скачать резюме".

------------------------------------------------------------------------

# Экран 2. Обо мне

## Цель

Дать понимание подхода к работе.

Не пересказывать биографию.

Рассказать:

-   чем нравится заниматься;
-   как строится работа;
-   что мотивирует;
-   почему именно системные задачи вызывают интерес.

------------------------------------------------------------------------

# Экран 3. Как я работаю

## Цель

Показать повторяемый подход.

Схема:

Исследование

↓

Понимание проблемы

↓

Проектирование решения

↓

Внедрение

↓

Получение результата

Это один из ключевых экранов сайта.

------------------------------------------------------------------------

# Экран 4. Кейсы

Главный раздел сайта.

Каждый кейс оформляется одинаково.

Структура:

-   задача;
-   контекст;
-   ограничения;
-   мои действия;
-   итоговое решение;
-   влияние на бизнес;
-   выводы.

Кейсы располагаются по силе.

Самые убедительные --- первыми.

------------------------------------------------------------------------

# Экран 5. Навыки

Не просто список технологий.

Навыки объединяются по смыслу.

Например:

Проектирование

Коммуникация

Аналитика

Управление

AI

Автоматизация

Инструменты

------------------------------------------------------------------------

# Экран 6. Опыт

Краткая временная шкала.

Без длинных описаний.

Для каждого места работы:

-   роль;
-   период;
-   основные достижения.

------------------------------------------------------------------------

# Экран 7. Образование и развитие

Показать постоянное обучение.

Не перегружать сертификатами.

Подчеркнуть стремление развиваться.

------------------------------------------------------------------------

# Экран 8. Контакты

Финальный экран.

Должен содержать:

-   фото;
-   короткий призыв к общению;
-   e-mail;
-   Telegram;
-   LinkedIn (при наличии);
-   GitHub (если будет);
-   кнопку скачивания резюме.

------------------------------------------------------------------------

# Навигация

Фиксированная верхняя панель.

Пункты:

-   Обо мне
-   Кейсы
-   Навыки
-   Опыт
-   Контакты

------------------------------------------------------------------------

# UX-принципы

Пользователь никогда не должен теряться.

Каждый следующий экран логически продолжает предыдущий.

Переходы плавные.

Важная информация располагается выше второстепенной.

------------------------------------------------------------------------

# Финальный путь пользователя

1.  Заинтересовался.
2.  Понял специализацию.
3.  Увидел подход к работе.
4.  Ознакомился с кейсами.
5.  Убедился в опыте.
6.  Захотел связаться.

Если этот путь проходит естественно, архитектура считается успешной.
