## Цель проекта

Персональный сайт-портфолио Екатерины, который одновременно работает как современное резюме и демонстрирует уровень её профессионального мышления. Целевые роли: Project & Operations Manager, Product Operations Manager, Project Manager, Product Manager (Junior/Middle), Operations Manager.

Главная цель — не понравиться визуально, а получить приглашение на интервью. Критерий успеха сформулирован в [01_Positioning.md](01_Positioning.md):

> «У этого человека уровень мышления значительно выше, чем ожидаешь от его опыта. Нужно обязательно поговорить с ним лично.»

## Текущий статус проекта

- Технический каркас уже развёрнут: React + TypeScript + Tailwind CSS v4 + shadcn/ui + Magic UI + Framer Motion (Vite). Структура компонентов задана: `Navbar`, `Hero`, `TechMarquee`, `Projects`, `Footer`.
- **Контент в коде сейчас — шаблонный placeholder**, никак не связанный с Екатериной (например, Hero сейчас содержит текст «Product engineer crafting fast, considered interfaces» — это заглушка из исходного темплейта, не финальный текст).
- Документация проекта (концепция, позиционирование, факты о Екатерине) подготовлена и организована в `docs/`.
- **Документация прошла критический аудит** (взгляд Senior Product Designer + нанимающего менеджера) — найдены слабые места в исходной концепции (см. [06_Concept_Review.md](06_Concept_Review.md)), по итогам обсуждения приняты решения и внесены в `Knowledge_Base.md`. Это не отменяет 01–05, а уточняет и достраивает их.
- Разработка контента под документацию ещё не начиналась.
- **Этап проекта: контентная база подготовлена и пересмотрена по итогам ревью. Следующий шаг — согласовать Hero-текст и финальный состав/порядок кейсов, затем приступить к итеративной разработке экранов.**

## Какие решения уже приняты (не обсуждаются заново)

- Структура сайта по экранам: Hero → Обо мне → Как я работаю → Кейсы → Навыки → Опыт → Образование и развитие → Контакты (см. [04_Site_Architecture.md](04_Site_Architecture.md)).
- Целевые роли и целевая аудитория (см. [01_Positioning.md](01_Positioning.md)).
- Tone of voice: спокойный, профессиональный, уверенный, честный, лаконичный — без громких обещаний и инфоцыганского стиля.
- Технический стек: React, TypeScript, Tailwind CSS, shadcn/ui, Magic UI (точечно), Framer Motion.
- Визуальное направление: светлый фон, один акцентный цвет, много воздуха, карточки с крупными радиусами, спокойные анимации (fade/slide/микроанимации) — без градиентов, стеклянных эффектов, каруселей.
- Правила публичного описания кейсов: без внутренних названий, реальных цифр, имён сотрудников — см. [Knowledge_Base.md](Knowledge_Base.md#facts-useful-for-the-website).

## Что нельзя менять самостоятельно

Прямой запрет из [05_Implementation_Brief.md](05_Implementation_Brief.md):

- Структуру сайта.
- Порядок экранов.
- Позиционирование.
- Смыслы (переписывание сути тезисов и кейсов).

Любое такое изменение сначала предлагается и аргументируется, а не выполняется сразу.

## Что можно предлагать

- Порядок и отбор кейсов внутри раздела «Кейсы» (документация прямо говорит: «Кейсы располагаются по силе. Самые убедительные — первыми» — но какие именно самые убедительные, решает не код, а согласование; рабочий отбор из 11 в 5–6 — в [Knowledge_Base.md](Knowledge_Base.md#projects-кейсы), не финальный).
- Конкретные формулировки Hero и других текстов (черновики — в [Knowledge_Base.md](Knowledge_Base.md#hero-ideas) и [Knowledge_Base.md](Knowledge_Base.md#quotes)) — как варианты на выбор, не как готовое решение.
- Визуальные решения для доверия без скриншотов (авторские реконструкции диаграмм/схем для ключевых кейсов, мета-прозрачность как текстовая рамка — см. [Knowledge_Base.md](Knowledge_Base.md#trust-strategy--доверие-без-скриншотов-и-точных-цифр)).
- Сокращённый, сгруппированный набор инструментов для показа на сайте вместо полного факт-листа с уровнями владения.
- Новый блок с масштабом/цифрами и слияние экранов «Обо мне» + «Как я работаю» — обе идеи из ревью, требуют согласования как изменение структуры.
- Акцентный цвет и детали визуального стиля — документация прямо говорит, что акцентный цвет определяется позже, после фотосессии.
- Улучшения структуры кода/компонентов, не затрагивающие смысл и архитектуру сайта.
