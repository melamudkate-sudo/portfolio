# 05_Implementation_Brief.md

# Роль

Ты выступаешь не как автор концепции, а как дизайнер и разработчик.

Концепция, структура и позиционирование уже определены отдельными
документами проекта.

Твоя задача --- реализовать их максимально качественно.

------------------------------------------------------------------------

# Основная цель

Создать персональный сайт-портфолио, который производит впечатление
зрелого цифрового продукта и помогает получить приглашение на интервью.

Главный критерий успеха:

После просмотра сайта работодатель должен захотеть пообщаться с
кандидатом.

------------------------------------------------------------------------

# Обязательно изучить перед началом работы

1.  01_Positioning.md
2.  02_Personal_Brand.md
3.  03_Design_Direction.md
4.  04_Site_Architecture.md

Нельзя начинать дизайн до полного понимания этих документов.

------------------------------------------------------------------------

# Приоритеты

При возникновении конфликта использовать следующий порядок:

1.  Пользовательский опыт (UX)
2.  Понятность
3.  Контент
4.  Визуальный дизайн
5.  Анимации
6.  Необычные эффекты

------------------------------------------------------------------------

# Требования к дизайну

Сайт должен ощущаться:

-   современным;
-   дорогим;
-   спокойным;
-   уверенным;
-   профессиональным.

Он не должен выглядеть как сайт дизайн-агентства или экспериментальный
лендинг.

------------------------------------------------------------------------

# Требования к разработке

Использовать:

-   React
-   TypeScript
-   Tailwind CSS
-   shadcn/ui
-   Magic UI (точечно)
-   Framer Motion

Компоненты должны быть переиспользуемыми.

Код --- чистым и масштабируемым.

------------------------------------------------------------------------

# Анимации

Каждая анимация должна отвечать на вопрос:

«Зачем она здесь?»

Если ответ отсутствует --- удалить.

Допустимы:

-   fade;
-   slide;
-   микроанимации;
-   плавные переходы.

Недопустимы:

-   хаотичные движения;
-   постоянные эффекты;
-   отвлекающие элементы.

------------------------------------------------------------------------

# Кейсы

Каждый кейс оформлять как самостоятельную историю.

Минимальная структура:

-   проблема;
-   контекст;
-   ограничения;
-   действия;
-   решение;
-   результат;
-   вывод.

------------------------------------------------------------------------

# Hero

Hero --- самый важный экран.

За первые 10 секунд он обязан ответить:

-   Кто перед пользователем?
-   На какую роль претендует кандидат?
-   Почему стоит продолжить просмотр?

------------------------------------------------------------------------

# Что запрещено

Не принимать самостоятельно решения о:

-   структуре сайта;
-   изменении порядка экранов;
-   изменении позиционирования;
-   переписывании смыслов.

Все подобные изменения сначала должны быть предложены и аргументированы.

------------------------------------------------------------------------

# Подход к реализации

Работать итерациями.

Каждый экран проходит цикл:

1.  Черновик.
2.  Согласование.
3.  Доработка.
4.  Финальная реализация.

Не переходить к следующему крупному разделу без согласования
предыдущего.

------------------------------------------------------------------------

# Финальная цель

Получить сайт, который можно использовать как основное портфолио при
отклике на вакансии уровня Project Manager, Product Operations Manager,
Product Manager и Operations Manager.

Ключевой принцип проекта:

Красота усиливает содержание, но никогда его не заменяет.
